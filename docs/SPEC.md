# Loom 首版实施规格

状态：用户于 2026-10-08 授权开始实施，2026-10-20 更新逐 Task 集成契约。本文记录行为要求，不作为逐项实现状态清单。执行准备架构见 [unit-execution.md](unit-execution.md)，其中记录执行边界与验证要求。设计决定见 [DESIGN-NOTES.md](../DESIGN-NOTES.md)，0.3 原型仅作交互参考，不能把演示逻辑当正式调度器。

## 目标

用户在本地 Web UI 中打开自己的项目，独立与 Codex 对话，或启动一个 DAG。任务内的 Agent 通过配套 CLI 显式提交结果，程序调度审查与返修，自动保存 Git 候选，并逐 Task 验证、集成到 Graph 专用分支。全过程可以查看真实运行记录。

## 行为要求

- R01 项目与持久化：应用只监听 loopback。打开现有本地目录；项目执行记录放在 .newharness 中。重新打开能够读取历史，不能把运行中的旧进程误认为仍然存在。
- R02 自由会话：可创建多个自由会话，各自独立历史，实际调用 Codex。自由会话与 Task 会话在界面分区。每个会话同一时刻最多一个活动 turn，正常后续对话恢复其运行时 thread。
- R03 可观察性：记录会话、turn、原始运行事件、工具输入输出、时间和 input／cached input／output tokens。每个 Agent Unit 单独累计；cached input 属于 input 子集，总量不重复相加。无法可靠取得的数据标记未知。程序 Unit 不产生模型 tokens。
- R04 模板：AgentTemplate 和 TaskType 跨项目复用，Task 实例保存版本及配置快照。成员支持 model、reasoning、skills、prompt 和工作区权限配置。库更新不回写现有运行。
- R05 DAG：Graph 中 Task ID 稳定，依赖必须存在且无环。允许独立分支并行；下游只能在所有前置成功集成后启动。Task 启动时固定 Graph 当前集成 HEAD，可能包含无依赖关系但已集成的成果。正在执行的 Task 保持原起点。Scheduler 和 Unit Preparation 为内部能力，不显示为图节点或额外成员。
- R06 TaskType：配置成员及结果到动作的规则。首版内置直接交付和 worker/reviewer 返修两种类型，以数据定义规则；不另调用调度模型。支持 Command Unit 验证。完整可视化规则编辑器后续实现。
- R07 CLI 汇报：提供结构化 CLI report 命令，身份从本次运行凭据确定；绑定实际报告文件并固定内容。重复相同请求返回已有凭证，过期运行、无权限身份、非法结果或文件不存在必须拒绝。报告结构不内置 public/audit/handoff。
- R08 交卷与结束：收到 report 不代表 turn 已结束。只有本次执行正常结束、有效结果已保存且工作区可固定时，才推进规则。正常结束但漏报，复用原 session 提示补报，按上限收口；失败和中断不按漏报自动续跑。
- R09 审查返修：无 reviewer 的类型允许 worker 交付；有 reviewer 必须审查当前候选后通过。返修与再审默认各自原 session。审查期间 worker 不再写同一工作区。候选变化后旧审查结论不能放行。
- R10 Git 工作区：每个 Graph 首次运行时固定项目已提交 HEAD，创建专用集成分支。当前仅开放独立 Task worktree；Task 启动前持久保存本次固定的 Graph 集成 HEAD，并从该提交创建工作区，不在启动时另合并依赖列表。Task 之间不共享可写工作区；未验收成果不得进入 Graph 集成分支。
- R11 快照与集成交付：由程序在安全边界固定 Git 候选，不要求 agent 提交。有效 report、本轮正常结束及配置要求的审查通过后，TaskType finish 将不可变候选放入每 Graph 串行交付队列。程序在隔离工作区合并候选，在实际合并结果运行可选集成验证，通过后才原子推进 Graph 分支并登记交付。未配置验证命令也明确记录。冲突或验证失败阻塞该交付，不推进分支，下游继续等待，独立队列项仍可继续。发布结果未知时先核对 Git 回执，不能假定分支未推进或盲目重试。保存候选与实际集成提交的独立身份、验证结果及操作记录。所有 Task 集成后 Graph 完成，不再进行整图最终合并。SHA、内部引用和日志默认仅在 Debug 展示，不自动合并或推送项目原分支。
- R12 暂停：软暂停立即停止派新执行与新的交付出队，活动 Unit 和已开始的集成验证可收尾。硬暂停请求中断 Unit 和验证进程，在发布前检查中断并等待 Git 操作结束，保留 thread、代码及已经发布的交付。工作区停止写入且未知交付已核对后才能编辑。暂停期间不因消息、补报或返修自动启动，恢复由用户显式操作。
- R13 编辑：未运行或完全暂停时修改未交付任务；校验 DAG 后保存。修改目标后的 session 收到变更说明，旧候选审查作废。旧交付记录保留为 superseded，新候选使用新交付身份。发布结果未知时先核对，不能直接废弃可能已发布的交付。运行中追加任务保存当时活动任务集合，等待该集合完工后生效。已交付任务重开及传递失效暂不开放。
- R14 Mailbox：每 Graph 一个 Letter 索引，地址 graph/task/unit，图外使用 session/id。Letter 有发送者、多个收件人、20 个 Unicode 字符以内标题、报告文件引用与固定内容；收发件箱是同一索引的视图。逐接收者记录投递状态。
- R15 自动收信：未来 Unit 等启动时注入；活动 turn 用已验证的输入接口投递；followup 等结束后继续同一 thread。已完成任务答疑不能重开任务或恢复代码写入。运行时不支持的模式须明确拒绝/标明，不静默冒充已投递。
- R16 订阅：主控可选 blocked、blocked+完成报告、再加单次 review。通知与恢复分开，同一事件不重复唤醒。状态反映当前事实，事件记录其变化。
- R17 交付与恢复：每次运行有单独标识。服务意外停止后，旧活动执行标为中断/待恢复，不自动重放写入、合并或验证命令。显式恢复先核对持久交付记录、Git 发布回执及残留进程；已发布结果不得重复发布。交付重试沿用固定候选，不重新运行已经验收的 Agent。暂停、任务交付、Graph 完成是不同状态。追加屏障的 queued 与交付队列的 merge_queued 不得混用。
- R18 Unit 执行准备：首次 session 准备配置、Skills、初始 prompt 和指定上下文；原 session 续跑沿用已接受配置，只补充新的指令、报告、信件和显式变更。运行器每次仍应用实际参数和权限。初始化完成及材料消费以真实输入接受为准，不能以 threadId 或进程 handle 为准。UI 在 Unit Config／Context 中显示来源与实际输入，准备失败不产生伪造的投递回执。
- R19 工作流包：loom-matt、loom-pstack 等工作流包提供可复用工作方法，安装、选择及项目默认值均不自动向自由会话注入。用户显式调用后才加载；规划调用不等于授权运行图。Task 执行按已保存的具体成员配置加载，不要求用户逐个手动调用 Skill。
- R20 侧边对话：自由会话及每个 Task Agent 支持独立只读侧聊，固定源会话最近已完成轮次。侧聊不消费源信件，不改变源上下文、Task 状态或调度。只读限制覆盖文件、命令、网络和可用工具。运行中可排队追问，下一轮恢复侧聊自己的会话。
- R21 开发者访谈：默认关闭；配置提示词、Skills、模型与推理强度，可手动运行或在 Task 完成／阻塞时触发。访谈复用独立只读侧聊，按事件与源会话去重。Loom 保存原始回答或失败状态到意见箱，开发消耗独立统计。

## 实施边界与验证

原型阶段不要求旧接口和旧准备状态兼容。新契约直接替换旧实现并同步改调用方；无需添加迁移、双字段或旧执行路径。此决定不授权删除用户项目文件。

技术选择由实施核查决定：TypeScript 本地服务、静态 Web UI、进程级 Codex 适配器、独立 Git 适配器。官方 TypeScript SDK 与 App Server 能力不同；运行中投信及中断优先采用已验证的官方接口，不猜测 SDK 方法。外部运行协议必须留在适配器内。

程序以本地 API / CLI 为公开测试边界。实际临时 Git 仓库验证工作树、冲突与主分支不变；受控 runtime 验证报告早于退出、重复提交、漏报、暂停和恢复；真实 Codex 小型 smoke 验证适配器，浏览器验证用户流程。测试断言来自本规格，不重复实现算法。

安全边界是实现的一部分：本地服务不接受任意跨站写请求；运行凭据不发送到正常 UI；报告路径、项目路径、Git 操作参数必须校验。Reviewer 写测试的细粒度隔离需实际验证；未实现时只能提供明确的只读 reviewer，不能宣称 prompt 等于权限隔离。

## 暂缓部分

- 完整返工、重开和回退不在本次集成队列范围。已确认的后续设计为主控处理下游阻塞；返工复用 session，在当前 Graph HEAD 新建执行工作区；回退针对交付创建经过验证的逆向提交，不 reset 分支。影响判断检查实际提交和交付历史，不能仅看 DAG。详见 [后续设计](../DESIGN-NOTES.md#返工与回退的后续设计)。
- squash 与 merge commit 的产品选择仍待决定。实现采用的 Git 提交策略不代表这一设计问题已经定案。
- Graph 引用节点的数据与执行隔离、取消的最终语义，单独保留为后续切片，未定事项不伪装成已实现。Agentic 子会话不是 Graph 引用节点，沿用现有子成果和生命周期门禁。
- 不发布远程服务，不自动 Git push，不连接 Slack/邮件，不移植旧 task-graph 的状态机或 CLI 语法。
- 不将原型中的模拟费用、角色名硬编码调度或进程定时器视为正式能力。

## 当前施工切片

1. 项目存储与公开接口，可创建并重开项目和自由会话，持久化校验与 API 证据。
2. 真实 Codex 会话适配器，恢复、中断、活动输入及工具与 usage 事件。
3. Graph / Task Git 工作区、自动快照与逐 Task 集成队列，真实 Git 验证。
4. Web UI 接真实项目/会话/图/模板/记录接口，保留原型视觉与会话分区。
5. CLI 汇报与 TaskType 调度闭环，依赖、审查、返修、漏报处理。
6. 软硬暂停、Mailbox、订阅与恢复，连同边界整合验收。

切片完成必须附真实证据，任务图只登记实际完成，不把类型定义、模拟或结构校验当成交付。
