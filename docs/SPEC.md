# New Harness 首版实施规格

状态：用户于 2026-10-08 授权开始实施。本文是首版的权威行为契约。设计讨论见 DESIGN-NOTES.md，0.3 原型仅作交互参考，不能把演示逻辑当正式调度器。

## 目标

用户在本地 Web UI 中打开自己的项目，独立与 Codex 对话，或启动一个 DAG。任务内的 Agent 通过配套 CLI 显式提交结果，程序调度审查与返修，自动保存 Git 版本，最终只汇总到 Graph 基线。全过程可以查看真实运行记录。

## 行为要求

- R01 项目与持久化：应用只监听 loopback。打开现有本地目录；项目执行记录放在 .newharness 中。重新打开能够读取历史，不能把运行中的旧进程误认为仍然存在。
- R02 自由会话：可创建多个自由会话，各自独立历史，实际调用 Codex。自由会话与 Task 会话在界面分区。每个会话同一时刻最多一个活动 turn，正常后续对话恢复其运行时 thread。
- R03 可观察性：记录会话、turn、原始运行事件、工具输入输出、时间和 token usage。每个 Agent Unit 单独累计；没有可信价格表时费用显示未知，不伪造美元数值。程序 Unit 不产生模型费用。
- R04 模板：AgentTemplate 和 TaskType 跨项目复用，Task 实例保存版本及配置快照。成员支持 model、reasoning、skills、prompt 和工作区权限配置。库更新不回写现有运行。
- R05 DAG：Graph 中 Task ID 稳定，依赖必须存在且无环。允许独立分支并行；下游只能在所有前置已交付后启动。Preparation 由程序执行，不作为 LLM 成员。
- R06 TaskType：配置成员及结果到动作的规则。首版内置直接交付和 worker/reviewer 返修两种类型，以数据定义规则；不另调用调度模型。支持 Command Unit 验证。完整可视化规则编辑器后续实现。
- R07 CLI 汇报：提供结构化 CLI report 命令，身份从本次运行凭据确定；绑定实际报告文件并固定内容。重复相同请求返回已有凭证，过期运行、无权限身份、非法结果或文件不存在必须拒绝。报告结构不内置 public/audit/handoff。
- R08 交卷与结束：收到 report 不代表 turn 已结束。只有本次执行正常结束、有效结果已保存且工作区可固定时，才推进规则。正常结束但漏报，复用原 session 提示补报，按上限收口；失败和中断不按漏报自动续跑。
- R09 审查返修：无 reviewer 的类型允许 worker 交付；有 reviewer 必须审查当前候选后通过。返修与再审默认各自原 session。审查期间 worker 不再写同一工作区。候选变化后旧审查结论不能放行。
- R10 Git 工作区：每个 Graph 有专用基准 worktree，起点为创建时固定提交；每个 Task 可独立 worktree。启动时汇入依赖的固定成果，多依赖冲突 blocked，不影响独立分支。关闭独立 worktree 的任务串行，不能混入其他任务尚未验收的改动。
- R11 自动快照：由脚本在安全边界创建 Git commit，记录在 Task 运行数据；不要求 agent 提交。下游默认只接收准备好的工作区与报告，SHA、内部引用和日志仅在 Debug 展示。最终汇总冲突阻止 Graph 完成；不主动合并或推送项目主分支。
- R12 暂停：软暂停立即停止派新执行，活动 Unit 收尾，之后才能编辑；硬暂停请求中断并等待确认，保留 thread 和代码。暂停期间不因消息、补报或返修自动启动。恢复由用户显式操作。
- R13 编辑：未运行或完全暂停时修改未交付任务；校验 DAG 后保存。修改目标后的 session 收到变更说明，旧候选审查作废。运行中追加任务保存当时活动任务集合，等待该集合完工后生效。已交付任务重开及传递失效暂不开放。
- R14 Mailbox：每 Graph 一个 Letter 索引，地址 graph/task/unit，图外使用 session/id。Letter 有发送者、多个收件人、20 个 Unicode 字符以内标题、报告文件引用与固定内容；收发件箱是同一索引的视图。逐接收者记录投递状态。
- R15 自动收信：未来 Unit 等启动时注入；活动 turn 用已验证的输入接口投递；followup 等结束后继续同一 thread。已完成任务答疑不能重开任务或恢复代码写入。运行时不支持的模式须明确拒绝/标明，不静默冒充已投递。
- R16 订阅：主控可选 blocked、blocked+完成报告、再加单次 review。通知与恢复分开，同一事件不重复唤醒。状态反映当前事实，事件记录其变化。
- R17 交付与恢复：每次运行有单独标识。服务意外停止后，旧活动执行标为中断/待恢复，不自动重放写入和合并。暂停、任务交付、Graph 完成是不同状态。

## 实施边界与验证

技术选择由实施核查决定：TypeScript 本地服务、静态 Web UI、进程级 Codex 适配器、独立 Git 适配器。官方 TypeScript SDK 与 App Server 能力不同；运行中投信及中断优先采用已验证的官方接口，不猜测 SDK 方法。外部运行协议必须留在适配器内。

程序以本地 API / CLI 为公开测试边界。实际临时 Git 仓库验证工作树、冲突与主分支不变；受控 runtime 验证报告早于退出、重复提交、漏报、暂停和恢复；真实 Codex 小型 smoke 验证适配器，浏览器验证用户流程。测试断言来自本规格，不重复实现算法。

安全边界是实现的一部分：本地服务不接受任意跨站写请求；运行凭据不发送到正常 UI；报告路径、项目路径、Git 操作参数必须校验。Reviewer 写测试的细粒度隔离需实际验证；未实现时只能提供明确的只读 reviewer，不能宣称 prompt 等于权限隔离。

## 暂缓部分

- Graph 引用节点的数据与执行隔离、取消的最终语义、已交付节点改动对下游的传递失效，单独保留为后续切片，未定事项不伪装成已实现。
- 不发布远程服务，不自动 Git push，不连接 Slack/邮件，不移植旧 task-graph 的状态机或 CLI 语法。
- 不将原型中的模拟费用、角色名硬编码调度或进程定时器视为正式能力。

## 当前施工切片

1. 项目存储与公开接口，可创建并重开项目和自由会话，持久化校验与 API 证据。
2. 真实 Codex 会话适配器，恢复、中断、活动输入及工具与 usage 事件。
3. Graph / Task Git 工作区、自动快照和最终汇总，真实 Git 验证。
4. Web UI 接真实项目/会话/图/模板/记录接口，保留原型视觉与会话分区。
5. CLI 汇报与 TaskType 调度闭环，依赖、审查、返修、漏报处理。
6. 软硬暂停、Mailbox、订阅与恢复，连同边界整合验收。
